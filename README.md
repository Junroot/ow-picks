# 오버워치 유효 픽률

오버워치 공식 영웅 통계의 픽률은 **그 영웅이 밴당한 경기까지 분모에 포함**한다.
밴률이 높은 영웅은 실제로 뽑을 수 있었던 경기에서 얼마나 뽑히는지가 가려진다.

이 도구는 밴을 보정한 **유효 픽률**을 맵별·티어별로 보여준다. 설치 없이 브라우저에서 열면 된다.

```
유효 픽률 = 픽률 ÷ (1 − 밴률)
```

예: 그랜드마스터·아시아 기준 프레야는 픽률 7.6%로 중위권이지만 밴률이 84.2%다.
선택 가능했던 경기만 보면 유효 픽률 48.1%로 공격군 최상위가 된다.

## 화면

| 탭 | 내용 |
| --- | --- |
| 맵별 상위 영웅 | 게임 모드별로 묶인 맵 30개, 각 맵의 돌격/공격/지원 상위 N명. `모든 전장` 평균 대비 차이(▲▼)를 함께 표시 |
| 전체 순위 | 특정 전장의 전체 영웅을 유효 픽률·픽률·밴률·승률로 정렬 |
| 티어별 추이 | 영웅 하나의 유효 픽률을 브론즈~그랜드마스터로 비교 |

필터 상태는 URL에 들어가므로 링크를 그대로 공유할 수 있다.

## 구조

```
scripts/fetch_rates.py   수집기 (파이썬 표준 라이브러리만 사용, 의존성 없음)
site/                    정적 사이트 — 빌드 단계 없음
site/data/meta.json      영웅·맵·필터 메타데이터
site/data/PC_{티어}_{지역}.json
.github/workflows/update.yml   하루 1회 수집 후 GitHub Pages 배포
```

`overwatch.blizzard.com/ko-kr/rates/` 는 서버 렌더링 페이지라 HTML 안
`<blz-data-table allrows="...">` 속성에 영웅 전체의 승률·픽률·밴률 JSON이 들어 있다.
API 키나 브라우저 자동화가 필요 없다.

역할(role) 필터는 클라이언트 사이드라 서버 응답을 바꾸지 않는다. 그래서
`(티어, 지역)` 샤드 하나가 맵 31개(30개 + `모든 전장` 기준선)만 받으면
그 조합의 전 역할 데이터를 갖는다 → 총 744 요청, 약 2~3분, 데이터 1MB.

수집 범위는 **마우스 및 키보드(PC) · 경쟁전**으로 고정이다. 컨트롤러(콘솔)는 요청과
데이터가 두 배로 늘어나는데 메타가 크게 달라 함께 보기도 어려워 받지 않는다.
밴이 없는 빠른 대전은 유효 픽률이 원본 픽률과 같아 받지 않는다.
입력 장치는 `scripts/fetch_rates.py` 위쪽의 `INPUT` 상수로 바꾼다. 경쟁전을 가리키는
`rq` 번호는 사이트가 수시로 바꾸기 때문에 상수로 두지 않고, 매 실행마다 페이지의 rq
선택 상자에서 `경쟁전 - 역할 고정` 항목을 이름으로 찾아 쓴다(`detect_rq`).

수집기는 **원본 수치만 저장**하고 유효 픽률은 화면에서 계산한다. 계산식을 바꿀 때
데이터를 다시 긁지 않아도 된다.

## 영웅·맵이 늘어나면

코드를 고칠 필요가 없다. 목록을 어디에도 적어두지 않고 매번 사이트에서 읽는다.

| 추가되는 것 | 동작 |
| --- | --- |
| 새 영웅 | `allrows` 에서 역할·초상화까지 자동 수집. 순위·맵 카드·영웅 선택에 바로 나온다 |
| 새 맵 | 맵 선택 상자를 순서대로 훑어 자동 수집. 요청 수만 늘어난다 |
| 새 게임 모드 | `optgroup` 이름이 그대로 섹션 제목이 된다. 그룹 밖의 맵은 `기타`로 묶인다 |
| 새 티어·지역 | 필터 목록을 사이트에서 읽어 샤드 수가 자동으로 늘어난다 |
| 새 역할 | 영웅 데이터에서 역할을 유도한다. `app.js` 의 `ROLE_ORDER_HINT` 에 없으면 뒤에 붙고, 한글 이름이 없으면 원문을 그대로 쓴다 |

한글 표시 이름만 예외다. 새 티어나 새 역할은 `app.js` 의 `TIER_LABEL` / `ROLE_LABEL` 에
한 줄 넣기 전까지 영어 원문(`Champion` 등)으로 나온다. 데이터는 정상이다.

지워지는 경우도 안전하다. 예전에 공유된 링크에 사라진 영웅·맵·티어가 들어 있으면
빈 화면이나 404 대신 있는 값으로 되돌린 뒤 URL을 고쳐 쓴다.

반대로 페이지 구조가 바뀌어 파싱이 깨지면 워크플로가 배포를 멈춘다.
영웅 30명·맵 20개 하한선과 샤드별 맵 수를 확인하므로, 망가진 데이터가 조용히 올라가지 않는다.
직전에 배포된 사이트는 그대로 남는다.

## 로컬에서 실행

```bash
python3 scripts/fetch_rates.py --tiers All,Grandmaster --regions Asia
```

```bash
python3 -m http.server 4173 --directory site
```

전체 수집은 옵션 없이 `python3 scripts/fetch_rates.py`. 확인용으로 `--limit-maps 3` 을 쓰면 빠르다.

## GitHub Pages 배포

1. 이 폴더를 GitHub 저장소로 올린다.
2. 저장소 **Settings → Pages → Build and deployment → Source** 를 **GitHub Actions** 로 바꾼다.
3. **Actions → 통계 갱신 및 배포 → Run workflow** 로 첫 배포를 돌린다. 이후 매일 05:00(KST) 자동 갱신된다.

데이터는 저장소에 커밋하지 않고 Actions 산출물로만 배포한다 (저장소가 매일 커지지 않도록).

## 수치를 읽을 때 주의할 점

- 픽률은 플레이 시간 기준 점유율이라 **역할 내 합계가 슬롯 수만큼** 된다 (돌격 100%, 공격·지원 각 200%).
- 유효 픽률은 근사치다. 분모의 다른 영웅 플레이 시간도 밴 상황에 따라 변하고,
  "자리야가 밴됐을 때 다른 돌격군이 얼마나 늘어나는가" 같은 상호작용은 공개 데이터로 분해할 수 없다.
- **밴률이 높을수록 오차가 커진다.** 밴률 60%면 보정 배율이 2.5배, 85%면 6.7배다.
  60%를 넘는 항목에는 ⚠ 표시가 붙는다.
- 공식 통계는 표본 수를 공개하지 않는다. 낮은 티어의 특정 맵처럼 표본이 적은 조합은
  그냥 노이즈일 수 있다. 데이터가 부족하면 원본에서 `--` 로 오고, 여기서는 목록에서 빠진다.
- 모든 통계는 패치 시작 시점 스냅샷이다.

블리자드와 무관한 비공식 도구다. 원본 데이터의 출처는
[오버워치 공식 영웅 통계](https://overwatch.blizzard.com/ko-kr/rates/)다.
